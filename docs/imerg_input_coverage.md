# Input data coverage — what is fed to the model

Figures showing the observation streams behind the IMERG decoder runs: where the data is, when it
is available, and how much arrives per assimilation window. Generated by
[`scripts/imerg_input_coverage_figures.py`](../scripts/imerg_input_coverage_figures.py); output in
`plots/imerg_input_coverage/` as PNG (300 dpi) and PDF.

```bash
# all figures, on a compute node (the maps read a few hundred thousand rows per stream)
sbatch plots/.figs_cov.sbatch all

# one figure, a different window, or a whole 6 h window instead of a 1 h snapshot
uv run --offline python scripts/imerg_input_coverage_figures.py \
    --figure C01 --time 2023-01-15T00:00 --map-hours 6
```

## Figures

| id | file | what it shows |
|---|---|---|
| C01 | `C01_georing` | The geostationary ring as one field, coloured by 10.5 µm brightness temperature. |
| C02 | `C02_stream_panels` | Every stream separately, each on its own scale. |
| C03 | `C03_timeline` | Availability per platform, with the evaluation window marked. |

### C01 — the geostationary ring

SEVIRI, GOES-16 and Himawari all carry a 10.5 µm window channel, so they share one colour scale
and the three discs read as a single global field rather than three unrelated images. Cold cloud
tops are dark, warm surface bright — the ITCZ, the Sahara and the mid-latitude storm tracks are
all directly visible.

The seams between discs and the gaps at the poles are the ring's real coverage limits, not
plotting artefacts. The comb-like texture at high latitude is the o256 reduced Gaussian grid
thinning out in longitude.

### C02 — per-stream panels

Same window, one panel per stream, per-panel colour limits (2 m temperature, an IASI principal
component and a visible reflectance share no units).

Two things that look like bugs and are not:

- **The VIS discs are mostly dark.** At 12 Z the Himawari disc is in night and the GOES disc shows
  the terminator. That is what the model receives at that hour. Use `--time` to pick a window that
  suits the audience — `00:00Z` puts the sunlit side under Himawari.
- **Metop A/B/C IASI reads "no data in this window".** That is real, and it is the finding below.

### C03 / C04 — availability and volume

Both are built from each store's hourly offset index and date array, so they cost no data reads.
C04 aggregates the hourly counts to the model's 6 h assimilation window and plots on a log scale;
gaps are genuine outages.

## The finding: the JEPA runs have no IASI during the evaluation

The three Metop IASI **radiance** stores end well before the IMERG evaluation period:

| store | last observation |
|---|---|
| `metop-a-iasi-radiances-v1` | 2021-09-08 |
| `metop-b-iasi-radiances-v1` | 2023-05-31 |
| `metop-c-iasi-radiances-v1` | 2023-05-31 |

The IMERG inference window is **2023-06-01 → 2023-08-31**. Observation counts in that window:

| stream | observations |
|---|---|
| METEOSAT_SEVIRI_IR | 234.0 M |
| GOES_ABI_IR | 254.1 M |
| GOES_ABI_VIS | 255.6 M |
| HIMAWARI_AHI_IR | 247.6 M |
| HIMAWARI_AHI_VIS | 248.8 M |
| AVHRR | 289.8 M |
| METOP_IASI_PC | 223.5 M |
| **METOP_ABC_AVHRR_IASI** | **0** |
| SurfaceCombined | 49.1 M |

`METOP_ABC_AVHRR_IASI` is **18 of the 126 input channels** for `r15j90ns` and `z71y2ik8` — both
JEPA-backbone runs. So for the whole evaluation those models run with one of their eight input
streams empty. `xfaps4wq` (Forecast backbone) uses `METOP_IASI_PC`, which ends 2023-12-30 and is
fully present.

**Why this matters for the 2-step comparison.** It cuts in the JEPA model's favour — it reached
parity without its IASI stream — but it is a third confound on that head-to-head, alongside the
input-channel count (126 vs 339) and the analysis resolution (o96 vs N320). State it rather than
let it be discovered.

It is also a caveat on the presented skill itself: these numbers are what the JEPA runs achieve
*without* IASI, and are not necessarily what they would achieve inside the training period.

Related: the all-streams overlap window is bounded at the top by exactly this store, so a training
or evaluation period that wants every stream present ends 2023-05-31 for the JEPA input set (and
2023-12-30 for the `METOP_IASI_PC` set).

## Store layout notes

Useful if you extend these figures:

- Each observation zarr is a flat `data` array `(n_rows, n_cols)` with `colnames` in
  `data.attrs`, a parallel `dates` array, and an hourly offset index `idx_197001010000_1`.
- **Hour `h` since 1970-01-01 occupies rows `idx[h - 1] : idx[h]`**, not `idx[h] : idx[h + 1]`.
  Verified against `dates`; getting this wrong shifts every map by an hour.
- Differencing `idx` gives observations per hour for the entire archive without reading any data —
  that is how C03 and C04 are free.
- Coordinate column names are **not** consistent: the AVHRR store uses `latitude`/`longitude`
  where every other store uses `lat`/`lon`. Longitude conventions vary too, so the reader
  normalises to [-180, 180).
